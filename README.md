# 우당탕! 수학 레스토랑 2.0

초등 6학년 2학기 수학을 복습하는 3D 협동 요리 게임입니다. 학생마다 컴퓨터 한 대로 접속해 4~5명이 한 주방에서 재료를 손질하고, 굽고, 접시에 담아 서빙합니다. 재료를 손질하거나 구우려면 수학 문제를 풀어야 합니다.

- 혼자 체험, 모둠별 협동 요리 (모둠 수와 모둠 인원을 선생님이 정함, 25명까지). 한 판이 끝나면 결과를 12초 보여 준 뒤 모두 대기방으로 돌아옴
- 설치나 회원가입 없이 웹 주소로 접속 (학생은 별명과 방 코드만 입력)
- 3D를 켤 수 없는 컴퓨터에서는 자동으로 2D 화면으로 실행

---

## 1. 선생님이 처음 한 번 할 일

### 1-1. Firebase 준비 (실시간 학급방에 필요)
이미 `restaurant-1306b` 프로젝트가 연결되어 있습니다(`firebase-config.js`). 새 프로젝트로 바꾸려면:

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고 웹 앱을 등록합니다.
2. **Authentication → 로그인 방법 → 익명**을 사용 설정합니다.
3. **Realtime Database**를 만듭니다. 위치는 싱가포르(asia-southeast1), 시작은 잠금 모드.
4. **Realtime Database → 규칙** 탭에 `database.rules.json` 내용을 붙여넣습니다. 이때 `__TEACHER_PIN__`이라고 적힌 **두 군데를 선생님만 아는 숫자로 바꾼 뒤** 게시합니다.
5. `firebase-config.js`에 웹 앱 설정값을 넣습니다. `databaseURL`이 꼭 들어가야 합니다.

> **교사 핀은 공개된 곳에 올리지 마세요.** GitHub에 올리는 `database.rules.json`에는 `__TEACHER_PIN__` 그대로 두고, 실제 숫자는 Firebase 콘솔의 규칙에만 넣습니다. 핀을 바꾸려면 콘솔 규칙의 두 군데를 고치고 게시하면 됩니다.

### 1-2. 인터넷에 올리기 (GitHub Pages)
1. GitHub에 **새 공개 저장소**를 만듭니다. (지금 코드는 `jink67-gm/kitchen` 저장소의 `math-restaurant-3d` 브랜치에 있습니다. 그 저장소의 `main`에는 다른 게임이 있으므로 새 저장소를 권합니다.)
2. 아래 "올려야 하는 파일"을 새 저장소의 `main` 브랜치에 올립니다.
3. 저장소 **Settings → Pages → Deploy from a branch → main / (root)**를 고르고 저장합니다.
4. 1~2분 뒤 `https://아이디.github.io/저장소이름/` 주소로 열립니다. 이 주소를 학생에게 알려줍니다.

**올려야 하는 파일**: `index.html`, `style.css`, `theme.css`, `game.js`, `cloud.js`, `render3d.js`, `models.js`, `sfx.js`, `math.js`, `settings.js`, `items.js`, `stations.js`, `plates.js`, `orders.js`, `firebase-config.js`, `.nojekyll`, 그리고 `assets/`, `vendor/` 폴더 전체.

올리지 않아도 되는 것: `screenshots/`, `prototype-3d/`, `development-specs/`, `tests/`, `standalone-demo.html`, 각종 `.md` 문서.

### 1-3. 내 컴퓨터에서만 열어보기
파일을 더블클릭하면 열리지 않습니다(브라우저 보안 때문). 폴더에서 명령 창을 열고 `python -m http.server 8123`을 실행한 뒤 브라우저에서 `http://localhost:8123/`을 엽니다.

## 2. 수업에서 쓰는 순서

1. 선생님: 게임 주소를 열고 **학급방 만들기 (선생님)** → 교사 핀, 인원, 모드, 시간을 고르고 방을 만듭니다. 난이도는 그 전에 시작 화면에서 고릅니다.
2. 화면에 뜬 **6자리 방 코드**를 학생에게 알려줍니다.
3. 학생: 같은 주소에서 별명을 쓰고 **게임방 입장 (학생)** → 방 코드 입력.
4. 대기실에 학생이 모두 보이면 선생님이 **게임 시작**을 누릅니다. 모든 학생 화면에서 동시에 시작됩니다.
4. 선생님이 "게임 시작"을 누르기 전에 "시작 전에 인트로 보여 주기"를 켜 두면 학생 화면에서 약 50초짜리 인트로 《사라진 천재 셰프》가 나옵니다. 인트로 동안 게임 시간은 흐르지 않고, 모든 학생이 같은 순간에 게임을 시작합니다. 학생은 "건너뛰기"(Esc)로 자기 화면만 넘길 수 있고 친구들과 함께 시작할 때까지 카운트다운이 나옵니다. 선생님 화면의 "인트로 건너뛰기 (모두)"를 누르면 모두 2.5초 뒤 함께 시작합니다. 두 번째 판부터는 이 선택이 꺼져 있습니다.
5. 진행 중 선생님 화면에 팀 점수와 학생별 학습 표가 보입니다. 학생 화면에는 점수가 나오지 않고, 끝난 뒤에도 선생님 화면에 최종 팀 점수가 남아 있어 화면을 함께 보며 발표할 수 있습니다. **게임 종료**로 일찍 끝낼 수 있습니다.
6. 끝난 뒤 **학생별 결과 파일(CSV) 저장**으로 엑셀에서 열 수 있는 파일을 받습니다.

방을 만들 때 고르는 것:

| 항목 | 설명 |
|---|---|
| 게임 모드 | **협동 요리**: 모둠마다 주방 하나, 모둠원끼리 함께 요리 (2대2 대결은 없앰) |
| 모둠 수 | 1~6개 |
| 모둠 인원 | 2~5명 |

- 모둠 수 × 모둠 인원이 그 방의 최대 인원입니다(25명까지). 학생은 들어오는 순서대로 모둠에 번갈아 배정되므로, 다 오지 않아도 모둠마다 고르게 나뉩니다.
- 모둠끼리의 점수는 선생님 화면에서 비교합니다(예전의 "학급 주방 대항전"은 협동 요리에 모둠을 여러 개 만든 것과 같아 합쳤습니다).

학생이 중간에 끊기면 같은 컴퓨터·같은 브라우저에서 같은 방 코드로 다시 들어오면 됩니다. 같은 자리로 돌아옵니다.

### 난이도
| | 편안함 | 기본 | 도전 |
|---|---|---|---|
| 수학 문제 | 쉬움 | 보통 | 어려움 |
| 주문에 없는 재료를 미리 손질할 때: 정답 뒤 문제 없이 작업 | 2번 | 1번 | 없음 |
| 도마 연타 | 5번 | 10번 | 12번 |
| 주문 대기 시간 | 100초 | 75초 | 55초 |
| 굽는 시간 / 타기까지 | 느긋 / 2배 | 보통 | 빠름 / 짧게 |
| 러시타임 속도 | 1.2배 | 1.35배 | 1.45배 |

"세부 설정 (선생님용)"을 펼치면 항목별로 바꿀 수 있습니다. 손이 불편한 학생이 있으면 도마 연타를 3번으로 낮출 수 있습니다.

## 3. 게임 방법 (학생용)

- **이동**: WASD 또는 방향키. **사용**: 설비 앞에서 E 또는 Space.
- **주문 받기**: 새 주문이 오면 왼쪽 위 주문서의 "문제 풀고 주문 받기"(또는 Q 키)를 눌러 수학 문제를 풉니다. 재료 2개 요리는 1문제, 3개는 2문제(보너스 +20점), 4개는 3문제(보너스 +40점)이고 팀원이 나누어 풀어도 됩니다. 다 맞히면 그 요리의 재료는 모두 문제 없이 준비합니다. 푸는 동안 그 주문의 대기 시간은 멈춥니다(최대 40초).
- **재료 준비**: 상자에서 재료를 집어 도마(자르기)·화덕(굽기)·믹서(섞기)에 올립니다. 아직 받지 않은 주문의 재료를 올리면 그 자리에서 주문 받기 문제가 나옵니다. 가까이 가면 이름표가 뜨고, 화면 아래 "다음 할 일"과 노란 화살표가 순서를 알려 줍니다(요리 2개를 서빙할 때까지, 편안함 난이도는 계속).
  - 도마·믹서: 정답 뒤에 E나 Space를 여러 번 눌러야 끝납니다. 완성품은 직접 집습니다.
  - 화덕: 올려두면 저절로 익습니다. 다 익으면 꺼내고, 늦으면 탑니다.
- **접시**: 접시대에서 접시를 꺼내 플레이팅대에 놓고, 준비된 재료를 하나씩 올립니다.
- **서빙**: 완성된 접시를 들고 서빙 벨로 갑니다.
- **정리**: 손질 전 재료는 원래 상자에 돌려놓습니다(감점 없음). 손질한 재료는 보관대(5칸)에 두거나 쓰레기통에 버립니다(-8점). 더러운 접시는 싱크대에서 씻습니다.

### 점수
| 항목 | 점수 |
|---|---|
| 서빙 | 100 |
| 팁 (빨리 낼수록) | 최대 +20. 대기 시간이 지나면 0이지만 주문은 사라지지 않음 |
| 콤보 (14초 안에 연속 서빙) | +20씩, 최대 +100 |
| 참여 보너스 (온라인, 팀원 모두 한 문제 이상 정답) | 판마다 한 번 +50 |
| 손질한 재료·탄 재료 버리기 | -8 (0점 아래로는 안 내려감) |

마지막 40초(짧은 판은 마지막 20%)는 **러시타임**입니다. 주문이 최대 3개까지 늘고 발이 빨라집니다.

## 4. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| "교사 핀 번호가 맞지 않습니다" | 핀 숫자. 맞는데도 안 되면 Firebase 콘솔의 규칙이 최신 `database.rules.json`으로 게시되어 있는지 |
| "Permission denied" | 규칙이 게시되지 않았거나 익명 로그인이 꺼져 있음 |
| "방을 찾지 못했습니다" | 방 코드 6자리. 선생님 화면이 대기실까지 넘어갔는지 |
| "학급방 정원이 가득 찼습니다" | 방을 만들 때 고른 인원보다 많이 들어옴. 인원을 늘려 새 방을 만듦 |
| "게임이 이미 진행 중입니다" | 처음 들어오는 학생은 진행 중인 판에 못 들어감. 다음 판을 기다림 |
| 화면이 2D로 나옴 | 그 컴퓨터가 3D를 지원하지 않음. 게임은 그대로 할 수 있음 |
| 화면이 끊김 | 자동으로 그림자를 끄고 해상도를 낮춤 |
| 소리가 안 남 | 오른쪽 위 소리 버튼(크게 → 작게 → 끔). 브라우저는 첫 클릭 전에는 소리를 막음 |
| 아무것도 안 뜸 | 파일을 더블클릭으로 열었는지 확인. 웹 주소나 `localhost`로 열어야 함 |

## 5. Firebase에 대해 알아둘 것

- **보안 규칙이 하는 일**: 교사 핀 확인, 방을 만든 사람만 시작·종료, 다른 팀 주방은 읽기·쓰기 불가(점수만 공개), 학생 결과는 교사와 본인만 열람, 방마다 데이터 분리.
- **막지 못하는 것**: 같은 팀 학생이 프로그램을 조작해 자기 팀 점수나 주방 상태를 고치는 것. 서버 프로그램 없이 규칙만으로는 막을 수 없습니다. 교실 수업용으로는 감수할 수준이라고 판단했습니다.
- **교사 인증**: Google 로그인 대신 핀 번호 방식입니다. 핀을 아는 사람은 누구나 방을 만들 수 있으므로 핀을 학생에게 보여주지 마세요.
- **수집하는 정보**: 학생이 입력한 별명, 자리·팀 번호, 풀이 기록(정답·오답·힌트·단원), 서빙 횟수. 실명이나 계정 정보는 받지 않습니다. 별명에 실명을 쓰지 않도록 안내해 주세요.
- **비용(무료 요금제 Spark의 한도)**: 동시 접속 100개, 저장 1GB, 내려받기 월 10GB. 한도를 넘으면 요금이 나오는 대신 **그 달은 접속이 막힙니다**.
  - **동시 접속 100개가 가장 먼저 찹니다.** 학생 1명·교사 1명이 각각 1개입니다. 25명 학급 3개(78개)는 동시에 되지만 4개(104개)는 안 됩니다. 여러 선생님이 같은 시간에 쓰려면 학교(또는 선생님)마다 Firebase 프로젝트를 따로 만들어 `firebase-config.js`만 바꿔 쓰는 것을 권합니다.
  - 이 게임이 아끼는 방법: 학생 위치는 초당 약 3번만 보내고 가만히 있으면 보내지 않음, 방에서 나가면 연결을 바로 닫음, 메뉴·혼자 체험은 Firebase에 연결하지 않음, 선생님이 새 방을 만들면 그 컴퓨터에서 예전에 만든 방을 지움.
  - 내려받기(측정): 모둠 5명이 계속 움직이며 요리할 때 학생 1명이 초당 약 2.2KB를 받음(90%가 친구 위치). 25명이 5분 한 판 ≈ 19MB(통신 덧붙는 몫 포함) → 월 10GB면 약 500판. 저장은 방 하나가 수십 KB라 거의 차지 않습니다.
  - 사용량은 Firebase 콘솔 → Realtime Database → **사용량** 탭에서 볼 수 있습니다.
- **오래된 방**: 방은 자동으로 지워지지 않습니다. 학기에 한 번쯤 콘솔에서 `rooms`를 지워 주세요.

### `standalone-demo.html`과의 차이
이 파일은 더블클릭으로 열리는 예전 2D 체험판입니다. 2.0의 기능은 들어 있지 않습니다. 3D 화면, 실제 접시, 도마 연타, 굽기·타기, 보관대, 주문 대기열, 러시타임, 새 수학 문제가 모두 없고 규칙도 예전 그대로입니다(Q로 재료 버리기 등). 2.0은 여러 파일과 3D 모델을 쓰기 때문에 파일 하나로 만들 수 없어, 최신 게임은 반드시 `index.html`을 웹 주소로 열어야 합니다.

### 혼자 체험과 온라인의 차이
규칙은 같은 코드를 씁니다. 다른 점은 혼자 체험의 도우미 3명은 돌아다니기만 하는 장식이고, 참여 보너스가 없다는 것입니다.

## 7. 알려진 한계

- 실제 교실 컴퓨터에서의 3D 속도(FPS)는 측정하지 못했습니다. 개발 환경에 그래픽카드가 없었습니다.
- 25명 접속은 컴퓨터 한 대에서 브라우저 25개로 시험했습니다. 실제 기기 25대와 학교 와이파이에서는 시험하지 못했습니다.
- 소리와 캐릭터 움직임은 개발 중 직접 듣고 보지 못했습니다.
- 수학 문제는 계산이 맞는지만 자동 검산했습니다. 문장과 난이도가 학생에게 알맞은지는 선생님의 검토가 필요합니다.
- 태블릿·터치 조작은 "사용하기" 버튼만 있고 이동 버튼이 없어 키보드가 필요합니다.
- 3D를 못 켜는 컴퓨터의 2D 화면은 예전 그림 그대로입니다.

자세한 테스트 결과는 `TEST_CHECKLIST.md`, 단계별 변경 내용은 `DEVLOG.md`에 있습니다.
