# 1A 단계 — 독립 3D 주방 시제품 제작 (기존 게임 코드는 건드리지 않음)

## 목적
첨부한 참고 이미지의 3/4 고정형 카메라, 선명한 3D 요리대, 작은 셰프의 캐릭터 가독성, 밝은 입체 조명과 주방 밀도를 재현하되 독창적인 장면을 설계한다.

## 구현 범위
- 기존 게임 루트에 `prototype-3d/` 같은 별도 위치를 만들고 Three.js 기반 시제품만 제작.
- 3D 주방 하나: 타일 바닥, 벽면, 카운터, 도마, 팬/화덕, 접시, 원재료 통, 보관대, 쓰레기통, 싱크대.
- 플레이어 캐릭터 1명의 이동. 적어도 정면/측면을 구별할 수 있도록 세밀한 실루엣, 얼굴/앞치마/요리 모자.
- 도마 위 토마토, 팬 위 고기, 접시에 빵 + 고기 등 **재료가 실제로 보이게** 3D 또는 단순 표면 모델로 구현.
- 그림자·환경광·점광원, 바닥/조리대 재질, 성능을 고려한 텍스처 및 메시.
- 좌상단 주문 카드 2장(시제품), 타이머, 조리 게이지 샘플은 HTML/CSS 레이어로 표시.
- 렌더링 목표: 교실용 PC 1280x720에서 일관된 가독성, 일반 목표 30FPS 이상. GPU 환경 제한 시 미달 사유를 보고.
- 선택한 스크린샷과 화면 크기별 비교 결과 제공. 과도한 이펙트보다 식재료·작업대 구분이 우선.

## 하지 말 것
- 게임 본체(`game.js`, `cloud.js`) 교체, Firebase 변경, 주문/재료 로직 전면 구현.
- 오버쿡드 원본 에셋/맵 복제.
- 품질을 검증하지 않고 전체 프로젝트를 3D로 즉시 이식.

## 통과 조건
- 장면이 정상 렌더링되고 움직인다.
- 스크린샷에서 조리대·재료·캐릭터가 명확히 보인다.
- 실제 브라우저 콘솔 로그 확인, 에셋 로딩 오류가 없다.
- 실제 프레임 성능을 측정한다.
- 이 단계가 끝나면 사용자에게 스크린샷을 보여주고 명시적으로 승인을 요청한 후 멈춘다.
