# 10단계 — 통합 QA·성능·안전 배포

공통 원칙과 모든 단계 기록을 읽고 게임 전체를 실제 실행 테스트하라.

1. **필수 완주 테스트**: 원재료 집기→원통 반환 / 재료 집기→수학 정답→실제 도마 연타→완료물 회수 / 고기 올려놓고 떠나기→익음 회수 또는 탐→폐기 / 아이템 냉장 보관·원하는 재료 꺼내기 / 접시 위 재료 눈으로 확인→완성 접시 들기→서빙 / 더러운 접시 설거지 / 3주문 러시와 135% 이동 / 콤보·팁·점수.
2. 싱글, 4명 협동, 4인 2대2, 20~25명 팀 대항 운영, 학급방 분리, 데이터 복제·동시 서빙, 교사 대시보드, 통계 CSV를 각각 검사하라.
3. 성능 목표(예시): 일반 학교 PC Chrome/Edge에서 부드러운 2.5D 렌더링, 입력 지연 체감 적음, 누수/메모리 증가 없음, 누적 파티클 상한, 데이터 트래픽 감시. 실제 측정값과 조건을 보고하라.
4. 에러 로그·단계별 테스트 결과표에 `통과/실패/미검증` 정확히 구분. 실패한 항목은 고치고 회귀 테스트. Firebase 권한/비용/동시성/교사 인증 이슈 문서화.
5. `README.md`에 교사용 배포/학급방 운영/학생 접속/게임 조작법/Firebase 설정/보안 규칙/오류 대응을 정리한다. `standalone-demo.html`도 업데이트하고 로컬 데모와 온라인 구현의 차이를 명시.
6. 최종 수정 파일 목록, 이전 버전 대비 달라진 게임 화면 스크린샷, 테스트 결과, 남아 있는 한계, GitHub 배포 절차를 보고한다. **실제 배포는 접근 권한과 배포 대상이 확인된 경우에만 수행**하고 그렇지 않으면 배포 가능한 코드를 제공한다.

**최종 합격 조건**: '4명의 요리사가 바쁘게 일하고, 손질·굽기·씻기·플레이팅·직접 서빙을 수행하며, 원재료 반환/손질 후 보관/폐기와 주문 러시를 겪는 장면'이 영상이나 스크린샷과 실제 플레이에서 확인된다.
