# 8단계 — Firebase 실시간 동기화와 4~25명 수업 운영

공통 원칙·현재 게임 코드를 읽고 **온라인 동시성/보안/학급 운영**을 구현·검증하라. 로컬 시뮬레이션으로 성공한 것을 온라인 검증 성공으로 보고하지 말 것.

1. 4~5명이 같은 주방의 플레이어 위치·모션·들고 있는 재료·재료 출처·도마 연타 게이지·팬/오븐/믹서/싱크대 점유 상태·접시·보관대·주문 대기열·서빙 결과를 공유한다.
2. 20~25명은 4~5명 팀 여러 개로 구분하고 팀 간에는 점수/순위만 전송. 게임방/팀 경로별 구독, 저비용 위치 전송, 다른 플레이어 보간. 학급마다 `roomId` 데이터 격리.
3. 여러 명이 같은 아이템 집기/보관대 선택 회수/조리대 점유/완성접시 서빙을 동시에 눌러도 원자적으로 단 한 번만 성공하도록 트랜잭션 및 유효성 검증. `onDisconnect`·재입장·서버 기준 시간 사용.
4. 학생은 익명 인증+코드·별명으로 입장. **관리자/교사 기능은 코드만 알거나 클라이언트에서 `role='teacher'`를 쓰는 것으로 획득하면 안 된다.** Google 로그인 등 검증 가능한 교사 인증이나 서버가 발급·검증하는 권한 방식으로 구현하라. Firebase Rules를 실제 데이터 경로에 맞춰 최소 권한 적용하고 위험한 전체 허용 규칙을 배포하지 말라.
5. 교사 대시보드에서 학급 인원/팀/라운드 시간/수학 단원/난이도/협동·2대2·학급 대항전/점수/학생별 수학 결과/CSV를 관리. 5명 팀은 2대2 모드 대신 학급 팀 대항전으로 운영.
6. 온라인과 단독 데모의 규칙 차이(특히 러시타임·팬 타기·게이지·플레이팅)를 점검한다.

**검증**: 실브라우저 4클라이언트 동시 테스트, 두 명 동시 상호작용 충돌 테스트, 독립 2개 학급방 비교, 네트워크 끊김 후 재접속. 20~25명 규모는 실제 장비가 없으면 시뮬레이션은 '모의 부하', 실테스트는 '미검증' 구분 보고. Firebase 자격증명/관리자 인증이 없어 수행 불가한 테스트도 솔직히 기록. 멈춰라.
