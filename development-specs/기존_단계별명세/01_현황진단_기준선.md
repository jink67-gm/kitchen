# 1단계 — 현재 게임 분석과 개발 기준선

`00_공통개발원칙.md`를 읽고, 현재 게임 저장소를 확인하라. **이번 단계는 기능 확장보다 조사·정리·테스트 환경 준비가 목표**다.

1. 현재 파일 구조, Canvas 렌더링, 이동·충돌·상호작용, 단일 주문, `held`, `tray`, 수학 모달, Firebase 팀 구조, standalone-demo 빌드 구조를 파악하라.
2. 동작하는 기능/버그/개발 우선순위 및 각 단계에서 변경할 상태 구조를 제안하라.
3. 안전한 변경을 위해 기존 프로젝트를 기준 커밋으로 남기거나 버전 백업하라(기존 작업을 덮어쓰지 말 것).
4. 브라우저 실행 방법과 재현 가능한 기본 테스트 시나리오(이동/재료 집기/문제 해결/서빙)를 문서화하라. 가능하면 Playwright 등 자동 스모크테스트 환경을 구성하되 불필요한 라이브러리를 대량 도입하지 말 것.
5. `ARCHITECTURE.md`, `DEVLOG.md`, `TEST_CHECKLIST.md`를 작성하라. 기존 코드에 문제가 있으면 분석 보고서에 기록하되 본격 리팩터링은 다음 단계에서 하라.

**완료 기준**: 무엇이 구현돼 있고 무엇이 미완성인지 정확히 보고하고, 현 버전을 실행해 기본 게임 플레이를 검증할 수 있어야 한다. 이번 단계 종료 후 멈춰라.
