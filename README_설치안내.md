# 🍳 우당탕! 수학 레스토랑 — 쿠킹 파티

초등학교 6학년 2학기 수학을 복습하면서 재료를 집고 손질하고 조리해 서빙하는 **실제 조작형 2.5D 쿠킹 게임**입니다. 학생마다 PC가 한 대씩 있는 수업을 전제로 하며, GitHub Pages에 올리고 Firebase Realtime Database에 연결하면 **한 학급 최대 25명**을 4~5명 팀으로 분리해 실시간 플레이할 수 있습니다.

## 파일 안내

- `standalone-demo.html`: 설정 없이 더블클릭하여 바로 실행하는 **1인 체험판**. 다른 학생 3명은 화면에 보이는 장식용 도우미 캐릭터입니다. 실제 협동 AI는 아닙니다.
- `index.html` / `style.css` / `game.js` / `cloud.js`: GitHub Pages 배포용 웹앱 본편.
- `firebase-config.js`: Firebase 웹 앱 설정 입력용.
- `database.rules.json`: Realtime Database 보안 규칙 예시.
- `preview-home.png` / `preview-game.png`: 테스트 화면 참고 이미지.

## 1. 체험하기 (Firebase 없어도 가능)

`standalone-demo.html`을 더블클릭해 열고 **먼저 혼자 체험하기**를 누르세요. WASD/방향키로 이동, E/스페이스바로 상호작용, Q로 재료를 내려놓습니다.

게임 흐름: 주문 카드 확인 → 해당 재료 상자에서 재료 들기 → 도마(손질), 화덕(굽기), 믹서(섞기) 중 맞는 장소로 이동 → 수학 문제 풀이 → 플레이팅대에 놓기 → 주문이 완성되면 서빙 벨 누르기.

## 2. 4~25인 온라인 학급방 설정하기

**이 단계는 교사가 직접 Firebase 프로젝트를 만든 다음 진행해야 합니다. 현재 제공된 파일에는 사용자의 Firebase 설정값이 없습니다.**

1. https://console.firebase.google.com 에서 새 프로젝트를 생성합니다.
2. 프로젝트 설정 → **웹 앱 등록** → `firebaseConfig`의 `apiKey`, `authDomain`, `databaseURL`, `projectId`, `appId`를 확인합니다. `databaseURL`은 웹 앱 구성에 표시되지 않으면 Realtime Database 화면에서 찾습니다.
3. Firebase 콘솔 → **Authentication → Sign-in method → Anonymous(익명)** 을 사용 설정합니다. 학생은 별도의 로그인 화면을 보지 않습니다.
4. Firebase 콘솔 → **Realtime Database** 를 만들고, **Rules** 탭에 이 폴더의 `database.rules.json` 내용을 붙여넣고 게시합니다. 테스트 모드에서 전체 읽기/쓰기를 공개하는 설정으로 사용하면 안 됩니다.
5. `firebase-config.js`의 빈 문자열을 웹 앱 설정값으로 변경합니다. 주의: **Firebase 웹 설정은 공개 가능한 클라이언트 식별자이지만, 서비스 계정 개인키 등 관리자 비밀키를 절대 넣으면 안 됩니다.**
6. GitHub의 새 공개 저장소에 `index.html`, `style.css`, `game.js`, `cloud.js`, `firebase-config.js`, `.nojekyll`을 업로드합니다. GitHub → Settings → Pages → Build and deployment → Deploy from a branch → main / root 를 선택합니다.
7. 배포 URL(예: `https://아이디.github.io/저장소명/`)을 학생들에게 전달합니다. Firebase Authentication 설정에서 **Authorized domains**에 해당 GitHub Pages 호스트명(`아이디.github.io`)을 추가해야 할 수 있습니다.
8. 교사는 **학급방 만들기**, 학생들은 **게임방 입장**을 눌러 6자리 코드를 입력합니다. 교사가 시작 버튼을 누르면 실시간으로 진행됩니다.

참고: 브라우저에서 JS 모듈을 불러오는 구조이므로 `index.html`을 파일로 직접 여는 것보다 **GitHub Pages나 로컬 HTTP 서버**에서 실행해야 합니다. Firebase SDK는 브라우저 CDN에서 불러오므로 온라인 접속이 필요합니다.

## 3. 수업 활용

- 4명: 4인 협동, 2대2 대결 중 선택
- 20명: 5명씩 4팀, 팀별 독립된 주방
- 21명: 5·4·4·4·4명, 5팀
- 25명: 5명씩 5팀
- 학급 대항전: 서로 다른 팀이 각자 주문을 완성하고, 인원 수를 보정한 팀 점수로 비교합니다.
- 한 판 시간: 3/5/7/10분. 교사는 실시간 점수를 확인하고 학생별 단원 풀이 결과를 CSV 파일로 저장할 수 있습니다.

**교육용 초기 버전**으로, 교사가 실제 수업 전에 컴퓨터 4~5대로 접속·재료 동기화·대결·인터넷 상태를 미리 확인하시기 바랍니다. 여러 학교 동시 부하 검증은 별도로 필요합니다.

## 4. 개인정보 및 운영 주의

- 학생 실명 대신 **별명**을 사용하도록 안내하세요. 게임방 코드가 외부에 노출되지 않도록 학급 내에서만 공유하세요.
- 익명 인증은 **가입 화면 없는 로그인**이지, Firebase 인증을 생략하는 것은 아닙니다.
- 예시 데이터베이스 규칙은 학급 코드의 비밀성과 익명 UID에 기반한 **기본 접근 제한**입니다. 이를 시험 성적처럼 민감한 학습 기록 보관이나 공개 대규모 서비스용 엄격한 보안으로 간주하면 안 됩니다. 학생별 기록은 가능한 단시간만 보존하세요.
- Realtime Database는 방이 종료된 뒤 자료를 자동 삭제하지 않습니다. 운영자는 보관 기간을 정해 오래된 `rooms` 노드를 삭제해야 합니다.
- 학생별 정답/오답은 교육용 피드백이며 보안상 확정 시험 점수에 사용하지 마세요. 실제 상용 규모에서는 서버 측 권한 검증 및 부하 시험이 필요합니다.
